# 影片轉圈圈健檢 · iPhone Video Buffering Doctor

在 iPhone 上打開就能跑的單檔網頁工具，約 70 秒實測後告訴你「IG／FB 影片一直轉圈」到底卡在哪一段，以及該怎麼改。

**➜ 直接使用：[開啟健檢工具](https://REPLACE_ME)**

零相依、單一 HTML 檔、所有測試都在你自己的瀏覽器裡跑，不上傳任何個人資料。

---

## 這個工具在做什麼

「影片轉圈圈」有四個可能的卡點，一般人分不出是哪一個。工具會逐一量出來：

| 關卡 | 量什麼 | 怎麼量 |
|---|---|---|
| **1. 網路夠不夠快** | 下載速度與持久力 | 持續下載 16 秒，用 `ReadableStream` 每 400 ms 取樣一次，畫出速度曲線 |
| **2. 線路穩不穩** | 延遲、抖動、掉包率 | 連續 20 次輕量請求，量 RTT 中位數、相鄰差值平均（jitter）、無回應比例 |
| **3. 連不連得到 IG／FB** | Meta CDN vs 對照組 | `no-cors` 探測 `scontent.cdninstagram.com`、`static.xx.fbcdn.net` 等，與 Cloudflare／Google／Apple 對照 |
| **4. 真的播一段影片** | 啟動時間、轉圈次數、卡住秒數、解析度 | 在頁面上實際播放測試串流，監聽 `waiting`／`playing` 事件計算 rebuffer |

跑完會輸出：一句結論 → 四個指標的紅黃綠燈量表 → 速度曲線圖 → 逐項診斷（每項附「設定 → 哪裡 → 哪裡」的完整路徑）→ 14 項 iPhone 必查清單 → 原始數據表。

## 怎麼用

1. **用 iPhone 的 Safari 打開上面的網址**（最準）。從 IG／FB／LINE 的連結點開會進到 App 內建瀏覽器，測不準——工具偵測到時會提醒你。
2. 在你「最常轉圈」的環境下測（在家就連家裡 Wi-Fi，在外就用行動網路）。
3. 照著紅色卡片改**一項**，回來按「再測一次」比數字。**一次只改一項**，才知道是哪一項有效。
4. 家裡 Wi-Fi 和行動網路各測一次，很能分辨是線路問題還是手機問題。

測試會用掉約 30–80 MB 流量。

## 判讀門檻

| 指標 | 健康 | 注意 | 有問題 | 依據 |
|---|---|---|---|---|
| 下載速度 | ≥ 5.5 Mbps | 3–5.5 | < 3 Mbps | Netflix 官方建議：1080p 需 5 Mbps、720p 需 3 Mbps |
| 掉包率 | < 1% | 1–5% | ≥ 5% | Cisco 影像 QoS 建議 < 0.5%，有緩衝的串流放寬到 1% |
| 抖動 | < 30 ms | 30–60 | ≥ 60 ms | 同上（Cisco 建議 10–50 ms） |
| 延遲 | < 150 ms | 150–300 | > 300 ms | 對有緩衝的串流延遲不是致命傷，僅作輔助指標 |
| 影片轉圈 | 0 次 | 1 次 | ≥ 2 次 | 直接觀測 |

**Meta 並未公布觀看端的頻寬建議值**，所以上表的頻寬門檻採用 Netflix 官方建議速度作為業界參考基準，工具介面內也如實標註。

## 三個被廣為流傳、但查證後不成立的「解法」

工具刻意不把這些當作主要建議，並在介面上寫明原因：

1. **關閉 iCloud 私密轉送 ≠ 修好 App 內轉圈。** Apple 官方文件寫明私密轉送只涵蓋 Safari 瀏覽與未加密的 App 流量；IG／FB App 的影片走加密 HTTPS，不經過它。只有用 Safari 開 instagram.com 網頁版看影片時才值得試。
2. **「清快取」查無官方依據。** 找不到任何 Apple 或 Meta 說法支持「快取太大造成播放問題」。而且 iOS 的「卸載 App」會保留 documents and data、不保證清掉快取；要真的清空只能刪除重裝。列為最後手段。
3. **IG 的「以最高畫質上傳」只影響上傳**，與觀看轉圈無關。

真正命中率最高的三項是：**Wi-Fi 的低數據模式**、**行動網路的低數據模式**、**低耗電模式**（會直接關掉 5G 與背景 App 重新整理，短影音因此無法預載，症狀正是「滑到下一則才開始轉圈」）。

iOS 設定路徑驗證於 **iOS 26.6**。iOS 27 推出後選單可能改名，屆時需重新驗證。

## 技術細節

- 單一 HTML 檔，**零外部相依**：沒有 CDN 腳本、沒有框架、沒有建置步驟。圖表是手寫的 inline SVG。
- **不使用 localStorage／sessionStorage**，所有狀態都在記憶體內，關掉頁面即消失。
- 深色／淺色模式皆已調校，並附主題切換鈕。配色遵循一套經對比度驗證的色票（狀態色一律搭配圖示＋文字，不靠顏色單獨傳達語意）。
- 圖表附**表格檢視**切換，符合無障礙要求。
- **優雅降級**：測速端點連不上時會依序嘗試備援來源；HLS 不支援時退回 MP4；任何一項測不到都會如實標示「測不到」，不會拿缺失的數據硬下結論。

測試端點（皆為公開服務）：

- 測速／延遲：`speed.cloudflare.com`，備援 `cdn.jsdelivr.net`、`unpkg.com`
- 測試影片：Apple `devstreaming-cdn.apple.com` HLS 範例串流，備援 Mux 測試串流與 Google 公開 MP4
- CDN 對照：Cloudflare／Google／Apple 的 favicon

## 測試

`tests/` 內是 Playwright 驗證腳本，用 `page.route` 攔截並模擬各種網路情境，確認診斷引擎在每種情況下都給出正確結論、且無 JS 錯誤。

```bash
npm i playwright
node tests/test.js     # 六種網路情境的診斷正確性
node tests/shot2.js    # 深色／淺色模式截圖
```

涵蓋情境：快速網路、頻寬不足、掉包＋抖動、Meta CDN 特別慢、完全斷線、以及各項量測失敗時的降級行為。
